# Specification Erratum: Cauchy Matrix Derivation and Branch-Number Wording

This note documents a specification discrepancy in Porter E. Coggins III, **“Multidimensional Hill Cipher Substitution-Permutation Network,”** *Journal of Cybersecurity and Privacy* 2026, 6, 104, DOI 10.3390/jcp6030104.

The correction concerns the prose specification of the Cauchy diffusion-matrix derivation in Section 3.9 and the description of the branch-number check. It does **not** change the implemented MD-Hill-SPN round function or the matrix-generation algorithm used by the Revision 3 reference and metric code in this repository.

## 1. Published specification discrepancy

Section 3.9 of the published article describes construction of an n x n Cauchy matrix over GF(2^8) using sets X and Y derived from SHA-256 output. The published prose states that zero bytes are replaced and collisions between X and Y are repaired. That description omits a required Cauchy condition: all 2n parameters must be pairwise distinct.

For a Cauchy matrix

```text
M[i][j] = (x_i XOR y_j)^(-1),
```

the x_i values must be mutually distinct, the y_j values must be mutually distinct, and X and Y must be disjoint. If x_i = x_j for i != j, two rows are identical. If y_i = y_j for i != j, two columns are identical. Either condition makes the matrix singular.

Jean-Philippe Aumasson observed that, when the published Section 3.9 prose is followed literally for the Appendix A test key, the 16 x 16 derivation yields a repeated X parameter (x_9 = x_11 = 0x87), so the resulting matrix is singular. That observation is correct with respect to the literal published wording.

## 2. Correct implemented derivation

The Revision 3 implementation in this repository uses a different, collision-safe parameter-selection procedure. For each required matrix, it creates an iterated SHA-256 byte stream keyed by

```text
master_key || tag || uint16(index) || uint32(counter)
```

and scans the resulting bytes sequentially. A byte is discarded if it is 0x00 or if it has already been selected for that matrix. A single duplicate-rejection set is shared across both X and Y. The first n accepted bytes form X and the next n accepted bytes form Y.

In pseudocode:

```python
X, Y = [], []
seen = set()

for b in stream:
    if b == 0 or b in seen:
        continue
    seen.add(b)
    if len(X) < n:
        X.append(b)
    elif len(Y) < n:
        Y.append(b)
    else:
        break
```

Consequently, all 2n selected parameters are distinct and nonzero. The matrix is then formed as

```text
M[i][j] = inverse_GF256(X[i] XOR Y[j]).
```

The matrix tags and indices are:

- `MDHILL_4`, indices 0 through 3;
- `MDHILL_8`, indices 0 and 1;
- `MDHILL_16`, index 0.

This is the algorithm implemented in `MD-Hill-SPN_test_vector_rev3_20260420.py`, `mdhillspn_metrics_corrected_2026_04_20.py`, and `mdhillspn_core.py`.

## 3. Prepublication provenance

The collision-safe Revision 3 reference implementation was committed to this repository on 22 April 2026, before publication of the journal article on 17 June 2026 and before the August 2026 critique. The current Revision 3 test-vector file retains the same Git blob as the prepublication version.

This chronology is important because it shows that the pairwise-distinct construction was not introduced in response to the later criticism. The discrepancy arose between the implemented algorithm and the prose specification that appeared in the published article.

## 4. MDS and branch number

For 2n pairwise-distinct Cauchy parameters, the standard Cauchy construction is MDS. Therefore the branch number reaches the Singleton bound:

```text
B(M) = n + 1.
```

Accordingly, the intended diffusion matrices have branch numbers:

```text
4 x 4   -> B = 5
8 x 8   -> B = 9
16 x 16 -> B = 17
```

The original article also described the branch-number computation as “exact via weight-1 enumeration.” That wording should be read more narrowly.

For an arbitrary matrix, testing only weight-1 inputs does not establish the true branch number. A singular matrix can have full-support columns and therefore pass a weight-1 check even though a higher-weight kernel vector gives a smaller branch number. For the valid Cauchy matrices generated by the implementation, the MDS property establishes B = n + 1; the weight-1 computation is an **implementation consistency check**, not an independent proof of MDS.

## 5. Effect on the repository and published results

No cryptographic algorithm change is made by this repository correction. The implemented construction already enforces pairwise-distinct parameters. The published Appendix A test vector, Round-0 intermediate values, 12-round ciphertext, decryption round trip, and repository conformance checks correspond to the collision-safe Revision 3 implementation.

The historical journal PDF is intentionally retained unchanged in this repository. It is the published record. This erratum documents the discrepancy rather than silently replacing that record.

## 6. Corrected specification text

A corrected replacement for the relevant Section 3.9 matrix-generation paragraph is:

> Each diffusion matrix of dimension n is constructed as a Cauchy matrix over GF(2^8). For each matrix, a deterministic byte stream is generated by successive evaluations of SHA-256 on the master key, a matrix-specific domain-separation tag, a two-byte matrix index, and a four-byte counter. The stream is scanned sequentially, discarding 0x00 and every byte value already selected for that matrix. The first n distinct nonzero values form X = {x_0, ..., x_(n-1)}, and the next n distinct nonzero values form Y = {y_0, ..., y_(n-1)}. Thus, all 2n elements of X union Y are pairwise distinct. The matrix entries are M[i][j] = (x_i XOR y_j)^(-1), with arithmetic in GF(2^8). Because all Cauchy parameters are pairwise distinct, every square submatrix has nonzero determinant and the resulting matrix is MDS. Consequently, B(M) = n + 1. The implementation additionally performs a weight-1 branch-number consistency check and fails closed if the expected value is not obtained.

The phrase “branch number computed exactly via exhaustive weight-1 enumeration” should correspondingly be replaced by:

> Branch number B = n + 1 follows from the pairwise-distinct Cauchy MDS construction; weight-1 enumeration provides an implementation consistency check.
